# 常见问题

## 没有 MUSA 设备，可以使用吗？

可以。离线比较、报告、趋势和安全张量分析仅需 NumPy；CPU 采集与算子预检另需 PyTorch。MUSA 执行、FP8 和专用框架功能需要各自依赖，见[安装](installation.md)。

## 找不到 `musaprobe` 命令

先确认安装时和执行时使用同一个 Python 环境。可以直接执行：

```bash
python3 -m musaprobe --version
python3 -m musaprobe --help
```

## 为什么没有张量文件？

默认 `mode="statistics"` 只保存摘要。逐元素比较需使用 `mode="tensor"`，并检查筛选规则、step/microbatch、预算、采集状态及实际执行的模块。先运行 `musaprobe inspect <采集目录>` 查看覆盖情况。

## `incomplete`、`truncated` 和 `fail` 有什么区别？

`fail` 表示已发现差异或错误；`incomplete` 表示证据不足以完成比较，例如只有统计摘要、缺失或不支持。`truncated` 是事件或载荷因预算等限制未完整保存的状态。身份未对齐（`unaligned`）和事件错误（`error`）也可能令总体 `fail`，需要读取具体原因，不能直接认定为模型数值缺陷。统计相近、文件缺失或采集被截断都不能作为逐元素比较通过的依据。

## 命令行退出码怎样解读？

| 退出码 | 常见含义 |
|---|---|
| `0` | 命令完成；比较/预检返回通过，配置比较返回一致 |
| `1` | 比较发现差异、预检不一致或配置不同 |
| `2` | 数据不完整、未知、不支持、非法输入或执行失败 |

具体看命令输出中的 `overall` 或 `status`。`inspect` 只检查元数据，成功退出不代表所有张量一致；`report` 只渲染现有比较结果。示例中的受控差异会有意产生 `fail`，这是对检测功能的检查。

## 两边都有相同的 NaN，能算通过吗？

不能。非有限值会单独报告；提高误差阈值也不会将非有限值、整数差异或结构不兼容改成正常浮点误差。见[运行比较](features/compare.md)。

## 为什么需要标记 step、microbatch 和 backward？

这些字段决定两次运行的事件身份。采集器无法替任意训练框架推断真实微批次和重计算调度。使用 `set_context()` 和 `backward_session()` 标记实际边界；多次 backward、共享模块等场景见[反向会话](features/backward.md)。

## 多 rank 的目录怎样组织？

所有进程使用同一 `run_id`，各写自己的 `rank_XXXXX`。不要把每个进程自动生成的 ID 混为一次分布式运行。热更新和安全停跑还需全部参与 rank 在一致边界调用协调接口，见[配置热更新](features/hot_reload.md)。

## 开启采集后变慢了，如何缩小开销？

先用统计模式，限制 step、rank 和模块；只有可疑区域才保存完整张量。按需设置切片和预算。API 采集、调用栈、FP8 保存和依赖记录都会增加工作量。异步写盘也需要固定快照与有限缓冲区，不能保证所有负载都加速。

## 报告的第一处差异就是根因吗？

它是已观察事件中的首处差异。未观察到的算子、输入或通信也可能影响结果。先核对输入、初始权重、配置和随机状态，再逐步扩大观察范围；执行图中的未知生产者保持未知。

## 编译或图模式可以直接套用 eager hooks 吗？

不能据此保证图内每次执行都有新数据。应使用[compile](features/compile.md)和[MUSA Graph](features/musa_graph.md)页的边界比较或显式探针，并检查 replay 代次。闭源融合内核的任意内部张量不在通用采集范围内。

## 报告可以公开分享吗？

HTML 可独立打开，但内容来自实际采集，可能包含模型名称、路径、调用栈或业务张量信息。请检查准备分享的副本。项目不自动上传采集文件。
