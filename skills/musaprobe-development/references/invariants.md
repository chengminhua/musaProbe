# 修改核心路径前确认的行为

这些是开发时最容易破坏的约定。具体字段和拒绝条件以当前源码及回归为准，用户接口说明见[功能手册](../../../docs/guide/README.md)。

## 依赖和数据格式

- 包名 `musaprobe`，显示名 `musaProbe`，Python 最低版本看 `pyproject.toml`。`import musaprobe` 与已有数据的离线比较/报告不应加载 torch 或设备运行时；PyTorch checkpoint 转换、采集和执行路径按功能加载。
- writer 输出 schema 2，reader 保持 schema 1 兼容。schema 2 的 `config_version`、`backward_id` 是身份信息，不可删除后冒充 schema 1；不改写历史数据来掩盖不兼容。
- 数字载荷使用安全 NumPy 格式，`allow_pickle=False`，校验路径归属、shape、dtype 和预算。PyTorch checkpoint 用受控 `weights_only` 路径；不要为未知对象开启任意 pickle 反序列化。
- 保存逻辑 dtype 与存储表示的区别。普通 BF16 数值载荷为 FP32；FP8 原始编码需要缩放、布局等完整状态，不能用 BF16 边界张量冒充。

## 采集生命周期

- 观察性采集应保持输出、loss、输入/参数梯度及相关 RNG 行为，清理自己的 hooks、dispatch mode、线程状态和待写任务。基准输入替换和主动停跑是显式干预，按其声明语义验证。
- `stop()` 暂停观察，`close()` 完成落盘和收尾。异常必须留有失败状态；已有 rank 输出目录拒绝覆盖。多 rank 使用同一个显式 run ID，不能让每个进程随机生成自己的运行名。
- step、microbatch、反向 session、重计算、VPP chunk 来自实际执行。共享模块和重复 backward 不得覆盖先前事件；无法归属的调用保留未知，不能凭事件顺序猜归属。
- 固定快照后才能交给后台写盘。验证调用后原地修改、队列背压、退出排空、写盘失败和缓冲区复用；MUSA D2H 要保留 stream/event 与内存生命周期约束。
- 热更新和停跑在调用方确认的安全步边界协调；多 rank 全部参与。控制组的失败不等于能够中断已挂起的设备 collective。

## 对齐和精度判定

- 语义身份不使用文件名、设备名或 `event_id` 作为跨运行同一性的证明。保留 rank、执行上下文、模块/API、调用序号、配置版本、切片和分片等证据。
- 显式名称映射仍需一对一和结构兼容。模糊匹配只提出候选；数值相近不能证明身份相同，歧义不自动接受。
- 整数/bool 精确比较，NaN/Inf 单独判异常。`statistics`、截断、缺失、不支持、读取错误或未对齐不能算完整张量通过；保持 `pass/fail/incomplete` 区别和 CLI 退出码契约。
- 浮点阈值与 FP32 ULP 由明确规则决定。CLI 显式值优先、规则冲突报错；不因现有实验失败就放宽默认阈值。首处观测差异是排查入口，不能直接写成根因。
- 趋势缺失点保留空档。依赖图只记录观察到的生产关系与明确通信身份，不凭调用先后或相同数值虚构因果边。

## 分片与特殊运行时

- 参数梯度 `main_grad` 优先不代表它已全局归约。分片优化器必须提供实际 ownership、范围、处理阶段和并行坐标；不 owned、缺接口或范围错误不回退为完整梯度，也不额外插入通信。
- 切片是采样范围，优化器分片是 ownership，二者不可混为同一种布局。重组要求完整、无重叠、阶段一致；缺片不补零。TP/PP/VPP 语义需要显式布局。
- compile/Graph 通过要求真的进入编译或图 replay 路径；图内探针验证 generation 和新输入，不读旧快照冒充新执行。不关闭图模式后宣称通过。
- 框架私有接口、FP8 状态布局和厂商插件按具体版本核查。vLLM 等适配存在不代表真实请求完成；本地 VeRL rollout 不代表分布式 RL 已支持。
