# 设备与远程实验

只在当前任务需要且已有授权的范围内使用设备。主机、账号、源目录、镜像和设备分配从当前会话及实时检查获得；本文件不提供固定目标，也不因某次曾空闲就授权下一次使用。

## 隔离与资源

实验新增数据放在 `/data/musaprobe-lab/<批次>/`，记录实际路径；源训练目录作为只读来源，需要修改时复制到任务目录并校验哈希。新增依赖只进入任务的隔离环境，优先复用兼容的现有镜像并记录镜像 ID。

共享机器上的默认实验上限如下；它们是资源上限，不代表机器当前有这些资源可用。任务另有明确资源约定时以该任务为准，不因一次实验失败就自行扩大资源或延长运行。

| 阶段 | CPU | 内存 | PID | 超时 |
|---|---:|---:|---:|---:|
| 小实验 | 4 核 | 16 GiB | 512 | 10 分钟 |
| 编译 | 最多 16 核 | 最多 128 GiB | 2048 | 30 分钟 |
| 大模型短跑 | 最多 16 核 | 最多 128 GiB | 2048 | 45 分钟 |

大模型先 2 步，通过后最多 8 步。任务新增数据默认预算 200 GiB，磁盘剩余不足 500 GiB 时停止新增数据；设置明确的 Tensor、rank 和事件预算。将模型缓存、编译缓存、临时文件和日志也重定向到任务的数据盘目录。

不修改现有 Kubernetes 资源、业务容器、驱动或系统组件，不使用特权容器或挂载 Docker socket。容器的 CPU/内存/PID/GPU 可见性必须由启动方实际设置并核对，不能只在报告里写限制数值。

## 逐级验证与停止条件

GPU 实验串行执行，按 CPU → 单卡 → 两卡 → 八卡扩大，每级依据对应目标决定是否需要下一阶段。每次开始前复核设备状态、业务进程与资源归属，出现其他训练/推理任务就避让；显存为零不是资源归属证明。

出现设备丢失、驱动错误、持续通信挂起或无法结束的 GPU 任务时停止后续设备实验并报告。不进行设备复位或驱动重启；只清理本任务创建的容器、进程和资源。异常注入使用受控数值偏差或 NaN/Inf。

## 已有工具的真实作用

- [check_lab_idle.py](../../../scripts/check_lab_idle.py)：读取 GPU 与磁盘状态，检查数据预算，向指定任务目录的 `host-checks/` 写证据。它不预留 GPU，也不枚举全部业务或 Kubernetes 调度状态；不能代替人工/调度分配核对。
- [run_bounded.py](../../../scripts/run_bounded.py)：在已受限的任务环境内运行命令，记录依赖、源码哈希、可见 cgroup 限制和退出码，超时尝试终止自己创建的进程组。**它不创建资源限制，也不持续监测磁盘。** 设备或进程无法退出时按前述停止条件处理；异常中断可能来不及生成 `run.json`，保留已有日志，不将缺少记录解释成成功。
- [remote_prepare_llama3.py](../../../scripts/remote_prepare_llama3.py) 与 [remote_launch_llama3.sh](../../../scripts/remote_launch_llama3.sh)：仅适配手册描述的特定 Megatron 启动结构；先查看帮助和 dry-run。源码结构不符时要单独适配，不删除检查硬跑。

`run_bounded.py` 当前只等待直接子进程退出：若它先退出而后代忽略终止信号，仍可能留下任务进程。命令结束或返回超时码后，复核本任务进程及设备资源确已释放，再决定是否继续；只向明确属于本任务的进程做清理，不凭名称批量终止其他作业。

下面只展示已有任务环境中的记录方式。`LAB` 必须已经建立；`IMAGE_ID` 替换为实际镜像 ID，源码仓库为当前目录：

```bash
LAB=/data/musaprobe-lab/本次批次
IMAGE_ID=实际镜像ID
python3 scripts/check_lab_idle.py --lab "$LAB"
```

确认即时检查与资源归属后，再运行需要的受限命令。例如先做 CPU 流程检查：

```bash
PYTHONPATH=src python3 scripts/run_bounded.py --lab "$LAB" --name cpu-smoke \
  --timeout 600 --image-id "$IMAGE_ID" -- \
  python3 examples/quickstart.py --device cpu --output "$LAB/quickstart"
```

该示例使用当前仓库的 `src`。验证源码改动时核对实际 `musaprobe.__file__`，不能让命令加载已安装的旧包、却只记录新源码的哈希。验证 wheel 时则离开源码目录并去掉 `PYTHONPATH=src`，核对导入来自新安装的产物。

原始日志与记录可能包含运行环境信息，留在实验输出目录；公开文档只摘取经过检查的支持范围与复现方式。对新设备/框架场景记录真实输入、源码哈希和正反例，使用[验收模板](../assets/validation-record.md)时按实际情况裁剪。
